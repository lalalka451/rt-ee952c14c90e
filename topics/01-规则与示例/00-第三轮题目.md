# 议题 01 · 第三轮：逐条投票

前两轮的经过在 `rounds/` 里。这一轮**只做一件事：逐条投票**。

投票规矩：
- 每条只投 **同意 / 不同意 / 有条件同意**（有条件就写清条件）
- 不同意要说**理由**，不接受「感觉不对」
- **不许投票时改题目**。想加新条目，单独写在最后，不进本轮统计
- 允许弃权，弃权要写为什么

---

## A 组：前两轮已达成的共识（确认一遍）

**A1** 成功标准 = 接得住 + 不像客服 + 不像剧本。多样性只是中间指标。
**A2** 规则定边界，示例管口气。规则要硬、可执行、可检验。
**A3** 宽场景（闲聊、玩闹）可留少量正例；重情绪场景默认零完整剧本。
**A4** 作者编的假漂亮话（如「……我心里一紧」）一律删。
**A5** 必须有运行时抽检：生成后跟示例库比对，命中就重采。只查 n-gram 不够，要加语义层。
**A6** 「语气能迁移，句子搬不过去」写进文件当元规则：用中等情绪场景示范口气，重情绪只用规则。
**A7** 示例库的终极形态是从真实交互日志里筛，不是作者继续编。进库前必须人工筛，防止她抄自己。

## B 组：真分歧（这轮要投出结果）

**B1 危机时要不要给求助渠道**
- 要（Hark、Muse）：识别出自伤风险，认真问清 + 给求助渠道
- 不要（pi）：私人陪聊不是公共产品，一弹渠道话术就变客服

**B2 被问「你是不是真人」能不能骗**
- 不能骗（Hark、Muse）：底线伦理
- 归作者定（pi）：这是角色设定，不是讨论能定的

**B3 能不能只示范结构**
- 能（Grok）：只写「先短反应 → 再追问」这样的骨架，不给金句
- 不能（pi）：结构也会被抄。实测：示例全删后，句子不抄了，但「短反应 + 追问」的两段式在八条回答里反复出现

**B4 多个示例能不能防抄**
- 能（Muse）：一个场景配 3–4 个不像的示例 = 分布
- 不够（Hark）：该看的是示例之间的差异度，不是数量
- 得分布在节奏上（pi）：只在句子上换没用，模型提取的是公约数

**B5 把示例打碎能不能防抄**
- 能（Muse）：打碎让它现场组装
- 不能（Hark）：被抄的「……」「我心里一紧」本身就是碎片

**B6 pi 现在这版（零示例 + 不哄不说理 + 无危机规则）能不能上线**
- 不能，风险最高（Hark）：没人检查过那八条里有没有一条在真实危机里是错的
- pi 需要回应
